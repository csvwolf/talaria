# 可选触觉录制

## 支持范围

蓝牙、USB 和 Puck／接收器均支持触觉输出。**录制目前仅支持蓝牙**：采集链路使用 Windows 蓝牙日志，不能用于捕获 USB／Puck 的触觉命令。通过蓝牙录制并保存的参数可用于三种连接；这表示参数可复用，不保证不同连接下的主观手感完全一致。

## 一次完整的录制验证

1. 先导出当前配置备份，通过蓝牙连接手柄，在「生效设备」重新选择它。
2. 开启 Steam，保留待录制触摸板的桌面绑定与触觉反馈，确认实际滑动、按压均有反馈。关闭其他震动测试工具。若之前为 Talaria 关闭了 Steam 的来源板绑定，录制前需暂时恢复。
3. 在「手柄输入设置 → 触觉反馈」中选择录制来源板，检查录制组件，然后开始录制。Talaria 会暂停接管；按界面阶段提示完成准备、静止、慢滑、快滑及按下／松开，避免同时触碰另一块板。
4. 等待解析和筛选完成。确认得到可编辑的滑动与按压反馈参数；仅生成日志或显示“已保存”不代表捕获成功。空结果、载荷缺失或只有“仅查看”条目都不能算通过。
5. 检查录制生成的配置与各事件参数。使用「试用」分别检查滑动、按下、松开和静止无误触；需要保留时「另存为」新名称，「应用」后才作为正式接管配置。未捕获的事件不要当作已录制成功。
6. 左板和右板各做一次。最后将同一份保存配置切到 USB、Puck 测试输出，每次重新选择生效设备；这一步验证输出兼容性，不是 USB／Puck 录制。

每次记录连接方式、来源板、Steam 状态、解析结果及测试时间，失败时保留对应日志。完成录制后恢复你原来的 Steam 桌面绑定，避免与 Talaria 重复输出。录制结果仅包含支持的触觉参数，不能完整复制 Steam 的鼠标算法或全部控制器设置。

## 组件与恢复

普通映射与预设不需要 Python。完整蓝牙录制需要 Python 3.9+、Windows WPR 和微软 BTETLParse.exe。请从微软 Bluetooth Test Platform 的官方来源取得分析工具；遵守其许可，勿上传到本仓库。

在「手柄输入设置」展开录制区域，点击「安装录制组件」。程序会复用已配置且验证通过的组件；缺少时从官方来源下载并校验固定 SHA-256：

- Python 3.12.10 嵌入式运行环境：安装到当前用户的 `Talaria/capture-tools`，不修改 PATH，也不影响其他 Python。
- Microsoft Bluetooth Test Platform 1.14.0：验证 Microsoft 签名后启动官方安装器，可能出现管理员确认；不会运行蓝牙测试或机器配置脚本。
- WPR 使用 Windows 自带组件。缺失时报告错误，不修改系统组件。

已配置组件时按钮显示「检查录制组件」，可直接录制或仅检查；检查不会下载安装，失败后显示「修复录制组件」。

安装完成自动保存工具路径；取消或失败可重新点击重试。「打开安装日志」在软件内显示，支持刷新和复制；提供步骤、版本、校验结果及错误码，日志位于 `%LOCALAPPDATA%/Talaria/logs/capture-setup-*.log`，不记录完整个人路径。原始安装包只下载到本机，不放入 Release。自定义安装仍可用 `configure-capture.ps1 -Python <python.exe> -Parser <BTETLParse.exe>`。

录制时按界面的准备、静止、慢滑、快滑、按压步骤操作。蓝牙诊断需要一次管理员授权；临时修改 BTHPORT 的三个诊断值，并在结束时恢复。不要同时运行其他蓝牙诊断工具。捕获可能包含其他设备内容，见隐私说明。

如果断电或进程被强制终止，管理员 PowerShell 中运行安装目录 `capture/Recover-Capture.ps1`。恢复信息保存在受 HKLM 权限保护的 `SOFTWARE/PadHopCaptureRecovery`，存在未完成恢复时拒绝新的采集。恢复脚本仅处理约定的三个诊断值，保留其他工具修改的不同值。异常类型需手动检查；驱动刷新失败时保留恢复信息。异常中断后的 WPR 会话可能还需根据采集目录 `trace-instance.txt` 用 `wpr -cancel -instancename <该会话名>` 单独停止，不要取消其他会话。

原始数据留在 `%LOCALAPPDATA%/PadHop/captures`，用户自行删除。已验证卸载组件并移走下载缓存后的完整下载、校验和安装流程；其他系统环境仍可能需要排查依赖问题。
